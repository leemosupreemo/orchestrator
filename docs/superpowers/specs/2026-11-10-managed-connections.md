# Managed connection repair

Approved scope: distinguish an offline computer from a failed web connection; repair the connection over the existing authenticated heartbeat channel; bounded retry and automatic failover to previously configured providers; guide first-time Tailscale Funnel account enablement and finish automatically; persist the selected provider for service reinstall, restart and project changes. Preserve running jobs and existing unrelated network services.

The computer owns a private machine-level connection store and manager. Provider operations and public probes run asynchronously, with single-flight repair, cooldown/backoff and finite attempts. Supported providers are the existing Cloudflare tunnel, Tailscale Funnel and an explicitly configured external HTTPS URL. A provider becomes selected only after its public path proves it reaches this runner. The probe must validate TLS, public DNS/relay addresses, no redirects, and a nonce/HMAC response from the runner; a private tailnet path or a live PID alone is insufficient. No API credentials or content leave the computer in health probes. Remote setup never grants account-owner permissions automatically or overwrites unrelated Tailscale routes.

Control-plane repair commands are owner-only, bounded/expiring and delivered until acknowledged, with idempotent IDs. The heartbeat publishes only sanitized connection status, provider, safe setup URL and endpoint metadata. A public health challenge reveals no project data or credentials. Existing old-runner reset behavior remains supported; new capabilities are versioned.

The UI shows Checking, Repairing, Needs setup, Connected or Connection unavailable alongside independent machine heartbeat state. Fix connection uses the control plane while the tunnel is down. Initial Funnel setup supplies the exact Tailscale owner enable link; once enabled, the computer finishes and verifies setup automatically. Stable snapshots remain visible until authenticated state succeeds. The selected provider persists per computer, including adoption of an existing --public-url service configuration.
